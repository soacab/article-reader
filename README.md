# Article Reader · 读文章

把本仓库的 GitHub 链接交给你的 coding agent，告诉它“请按首次安装步骤，让我的飞书机器人能总结文章、把原文存到我的笔记目录”。第一版面向 macOS、本机 Codex 和飞书。公开文章用本机网络读取；总结默认使用机器人的助手，也可以按机器人指定兼容 Chat Completions 的 API。需要微信验证时返回失败原因。Mac 和机器人后台服务需要在线。

## 给安装助手的首次安装步骤

1. 安装助手首先问「你要给哪个已有的飞书机器人添加读文章功能？」。列出本机已绑定的机器人名称及 App ID 供区分，只有一个也让用户选择。未列出的机器人先定位其现有后台和可信运行标识；需要接入 AAMP 时再按 [AAMP 安装说明](https://www.npmjs.com/package/@larktask/aamp-feishu-task-agent) 绑定已有机器人。若两个机器人共用 Codex，后台必须随每次请求传入各自标识。AAMP 会在 Dispatch Context 提供 feishu_lark_cli_profile。
2. 在机器人的执行端克隆仓库，用本机交互终端运行 `node install.mjs`（可追加技能父目录）。依次选择机器人、总结模式。默认沿用机器人的 AI；独立模式填写 Base URL、模型名称，在隐藏输入处粘贴 Key。安装助手可以引导用户在本机完成此步，勿让用户把 Key 发到聊天里。独立模式会用固定短文本试连，成功后写入 macOS 钥匙串。要求 Node 版本见 package.json，需 npm 和可访问的网络。升级时会保留旧版备份。
3. 配置按机器人存于本机 ~/.config/article-reader。独立模式把文章和用户本次阅读要求发给所选 API，指定 Key 承担摘要用量；宿主助手仍可能为理解消息及回复产生用量。只保存原文不调用摘要 API。连接或模型报错时原样告知失败，不自动回退。需要改选时运行 `node install.mjs --configure`，只更新选中的机器人配置。后台在服务器时，笔记写入执行端可访问的路径。
4. 在飞书向机器人发“请总结这篇的三个要点：〈公开文章链接〉”。对照原文检查三个具体要点。再发“把这篇原文保存到〈绝对目录〉：〈文章链接〉”，核对飞书回复、实际 Markdown 文件的来源、末段及成功保存的图片。目录应在执行端可访问范围内。
5. 记录每步结果。收不到消息查配对和收发权限；消息能达但没用技能查运行端；读取失败查实际错误；写入失败查目标目录权限。新安装、配对、飞书往返和写入分别核验。私有飞书文档另走用户自己的飞书文档工具与授权。

## 本地直接读取

在已安装技能目录运行 `node read.mjs 'https://example.org/article'`。保存可在命令末尾加 `--save-dir '/绝对路径/待读'`。抓取在独立进程中运行，失败时退出码非零；遇到重名文件自动选择新文件名。图片保存在笔记旁的独立附件目录里。

## 首次配对超时怎么办

如果飞书已完成授权，但 AAMP 的首次绑定在 90 秒时报超时，先用 `feishu-task-agent list` 核对新应用仍在绑定列表中，再查看 `feishu-task-agent status` 和 `logs`。本次 macOS 验收中，配对成功的一次用了 106 秒。对仍为 pending 的已有绑定，可以在交互终端运行 `AAMP_TASK_READY_TIMEOUT_MS=240000 feishu-task-agent start`，选择本次需要运行的绑定。若 AAMP 已经回退到只运行旧绑定，先告知用户已有机器人的短暂中断，在可中断时用 stop 后再运行上述 start。若机器上有多份 Codex，检查实际命中的 codex --version 与之前可用的版本。以飞书消息往返和后台服务的就绪状态验收。
